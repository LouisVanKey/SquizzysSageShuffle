# Squizzy's Sage Shuffle: Hero Picker

Static site (GitHub Pages) + Supabase free tier (Discord login and the public list of hero locks). Cost: €0.

Until `js/config.js` is filled in, the site runs in **demo mode**: everything works, but picks are only stored in your own browser.

## How it works

- `index.html`, `css/`, `js/`: the whole site, no build step.
- `js/heroes.js`: the 71 young heroes in Silver Age as of Mastery Pack Assassin (67 pickable, 4 benched: Briar, Chane, Oldhim, Oscilio), verified against LSS's Card Vault on 16 Nov 2026. Generated by `scripts/build_heroes.py`.
- `supabase/schema.sql` + `supabase/seed_heroes.sql`: database tables and the rules that enforce
  one hero per Discord account, one player per hero, no changes after locking, and organiser-only removal.
  These rules run in the database, so they cannot be bypassed from the browser.

## Setup (about 15 minutes)

### 1. Supabase project
1. Create a free account and project at https://supabase.com (region: EU).
2. SQL Editor: run `supabase/schema.sql`, then `supabase/seed_heroes.sql`.
3. Project Settings > API: copy the **Project URL** and the **anon / publishable key** into `js/config.js`.
   Never use the `service_role` key in the site.

### 2. Discord application
1. https://discord.com/developers/applications > New Application ("Squizzy's Sage Shuffle").
2. OAuth2 > copy the **Client ID** and **Client Secret**.
3. OAuth2 > Redirects > add `https://<your-project-ref>.supabase.co/auth/v1/callback`.
4. In Supabase: Authentication > Sign In / Providers > Discord > enable, paste Client ID and Secret.
   The secret lives only in Supabase, never in this repo.

### 3. GitHub Pages
1. Push this folder to a GitHub repo (public repos get Pages for free).
2. Repo Settings > Pages > Deploy from branch > `main`, `/ (root)`.
3. In Supabase: Authentication > URL Configuration, set **Site URL** to
   `https://<user>.github.io/<repo>/` and add the same URL under **Redirect URLs**.

### 4. Organisers
Enable Developer Mode in Discord, right-click your name > Copy User ID, then in the SQL Editor:

```sql
insert into public.admins (discord_id, note) values ('YOUR_ID', 'Louis'), ('BRECHTS_ID', 'Brecht');
```

Organisers see a **Remove** button under every locked hero.

## Testing the Discord login

1. Do steps 1 to 3 above, then open your GitHub Pages URL. The "Demo mode" label must be gone.
2. Click **Log in with Discord**. Discord should show an "authorize" screen naming your application and asking
   only for your username and avatar. After approving you land back on the page with "Welcome, <your name>".
3. Lock a hero. Open the page in a private window (not logged in): your hero must show under "Locked in"
   with your name and Discord tag. That proves the shared database works.
4. Ask a second person (or use a second Discord account) to try locking the same hero and a second hero:
   both must be refused.
5. Clean up the test picks (see below) before you share the link.

If login bounces back without logging you in, it is almost always one of: the redirect URL in the Discord
application is not exactly `https://<project-ref>.supabase.co/auth/v1/callback`, or your GitHub Pages URL is
missing from Supabase > Authentication > URL Configuration.

To test on your own computer first: run `python3 -m http.server 8000` in this folder, open
`http://localhost:8000`, and add `http://localhost:8000` to the Supabase Redirect URLs.

## Managing the locks

**On the site:** organisers listed in `public.admins` see a **Remove** button under every locked hero.
Removing a lock frees the hero and lets that player pick again.

**In Supabase (Table Editor > `picks`)** you can do everything, because the dashboard bypasses the site rules:

- Delete a pick: select the row > Delete.
- Give someone a different hero: edit the `hero_id` cell of their row (ids are in the `heroes` table,
  e.g. `kano`, `ira-crimson-haze`). The hero must not be taken by someone else.
- Add a player without Discord: Insert row with `hero_id` and `player_name`, leave `user_id` empty.
- Swap two players: set one row's `hero_id` to a free hero first, then fix both.

Or with SQL (SQL Editor):

```sql
-- overview
select h.name, p.player_name, p.discord_name, p.created_at
from picks p join heroes h on h.id = p.hero_id order by p.created_at;
-- move a player to another hero
update picks set hero_id = 'kano' where player_name = 'Louis';
-- delete one pick / all picks
delete from picks where player_name = 'Louis';
delete from picks;
-- freeze or reopen picking
update settings set locks_open = false;
-- allow a benched hero after all
update heroes set pickable = true where id = 'briar';
```

Free Supabase projects pause after about a week without any activity. Visiting the page counts as activity;
if it does pause, press "Restore" in the dashboard (no data is lost).

## Notes

- Images are loaded directly from LSS servers (used with LSS permission for this armory event): the circles are
  cropped from each young hero's own card, the pop-up uses the cut-out art from fabtcg.com's hero selector
  (those cut-outs only exist for the adult versions).
- Fonts: Tiller (headings) and Scala Sans Pro (body) are served from `assets/fonts` (converted to WOFF2 from the
  files supplied). Only one Scala weight was supplied, so bold body text is synthesised by the browser.
- Event date and venue shown on the page are set in `js/config.js`.
- Updating the hero list after a new set: download `card.json` from
  https://github.com/the-fab-cube/flesh-and-blood-cards and run `python3 scripts/build_heroes.py card.json`,
  then re-run `seed_heroes.sql`.
